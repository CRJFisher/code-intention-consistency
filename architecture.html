Intention Audit Trail

Proposed architecture — offline writes, inline reads

Intention-tree writes happen offline in a fire-and-forget side agent (claude-agent-sdk), so the coding session is never interrupted. The only inline touchpoints are two cheap, no-LLM guards: a read injection at planning time — the relevant historical intention slice for the region being worked, so the agent can FLAG (a past intention may be inadvertently overridden → surface to the user), REFINE, or PASS-THROUGH — and a commit guard that denies manual git commit so the audit writer stays the sole author of history. A thin deterministic Stop gate commits when fresh artifacts exist — no LLM in any hook.

1 · The shift

Before — inline 5-phase blocking loop

  • Every Stop runs a 932-line hook that spawns 5 LLM sub-agents in sequence.
  • Evidence phase runs pytest inline — up to a ~60s stall.
  • 16 MCP tools + 16 agent specs; the session is interrupted on every stop.
  • Reasoning lives on the hot path.

After — offline writes, inline read

  • One UserPromptSubmit read-injection (no LLM, <100ms) — the sole intrusion.
  • One detached offline writer agent does all analysis & persistence, off the hot path.
  • Stop becomes a ~250-line deterministic commit gate reading a run-manifest.
  • Reasoning is eventual & crash-isolated; the session never waits on it.

Why the commit guard is required. The audit writer is the sole author of commits — it is the only thing that stamps Intent-Id / Intent-Path trailers. If the main agent commits manually, two invariants break at once: the Stop / SessionEnd committer finds a clean working tree with nothing left to commit, and the manual commits enter history without trailers, leaving permanent holes in the audit trail. The PreToolUse guard closes this by denying commit-creating Bash commands and redirecting the agent to leave changes uncommitted. It is a best-effort guard, not a sandbox — an agent that writes and runs a shell script could still slip a commit through; the guard catches the direct invocations that matter in practice.

3 · The planning-time read-injection

The agent sees prior intent before it builds a plan, and decides what to do about it. No LLM call, no MCP, no git blame walk — just a working-tree scan and a cached index lookup.

4 · Offline write flow

Triggered after edits settle; runs detached; idempotent on diff_hash; can crash without ever touching the session or working tree.

5 · Simplification delta

All five phase sub-agents and the eleven analysis/research tools collapse into one offline writer; the five remaining tools are demoted to dumb persist-only endpoints called only by that writer.

6 · Migration steps

  1. Add inject_intent.py (UserPromptSubmit): git-status region inference + mtime-keyed file→intent index, reusing structure/boundary._path_within_prefixes; emit additionalContext with FLAG/REFINE/PASS-THROUGH and >10k spill. decision always allow.
  2. Add writer_launcher.py (PostToolBatch + SessionEnd): WAL append, 2s debounce, in-flight diff_hash check, detached claude-agent-sdk spawn, bounded SessionEnd drain.
  3. Author the single writer_agent prompt running the 5 phases in one pass, with run-manifest checkpointing and diff_hash idempotency (reuse _compute_diff_hash, _get_artifact_dir).
  4. Demote the 5 surviving MCP tools to persist-only: strip gating/decision logic, keep atomic temp+rename writes via existing models/.
  5. Rewrite stop_hook.py to the deterministic gate (three outcomes), reusing commit_builder.build_commit_message and the failure renderers. Delete the 5-phase spawn orchestration entirely.
  6. Delete the 11 analysis/research MCP tools + their agent specs; fold any still-wanted logic into config-gated writer sections. No shims, no deprecated re-exports.
  7. Add per-session .lock, wal.jsonl, side_agent.log, run-manifest.json to the store; keep .intent_audit/ gitignored; durable audit = git trailers.
  8. Replace 5-phase e2e tests with: (a) read-injection slice assertions, (b) offline writer idempotency/crash-resume, (c) the three Stop-gate outcomes. Update CLAUDE.md Hook Architecture to this design (canonical, present-tense).

7 · Risks & trade-offs

  • Eventual consistency: artifacts lag edits by debounce + writer runtime. A fast Stop right after a big edit hits "analysis in progress, retry" once. Mitigated by SessionEnd forced flush + bounded drain.
  • Loss of synchronous enforcement: the gate guides + audits but no longer hard-blocks a coverage gap mid-edit. Acceptable per the "guidance + audit, not interruption" goal; a thin ledger check can be re-added if hard enforcement is truly needed (YAGNI for now).
  • Detached-subprocess discipline: launcher must detach cleanly (no zombies) and SessionEnd must bound its drain so teardown never hangs.
  • Crash between phases leaves a partial run-manifest; resume must be idempotent on diff_hash or the gate stays blocked. Mitigated by per-phase checkpointing.
  • Heuristic region inference (git status + code_home) can pick an over-broad region → a less-relevant but never-blocking slice; the agent corrects on the next prompt.
  • Retained machinery (.lock, WAL, run-manifest, atomic renames) is more parts than a pure-minimal design — justified only around the single offline writer where real concurrency exists, and kept off the inline read path entirely.
